# Gesso — Review log
Each entry: date, scope, what was measured, what felt wrong, what got fixed, what was deferred.

## R0 — M1 build tests (2026-10-12)
- Synthetic test passes, with no console errors. 14 strokes take ~4.6 s under SwiftShader (CPU, not representative of a tablet's GPU). 600-sample wet stroke ~488 ms on CPU.
- Gestures: 2-finger undo, 3-finger redo, pinch/rotate, and palm rejection after pen detection all OK.

## R1 — M1 review: engine, stroke, input, UI (2026-10-12)
**Bar (how the best apps do it).** Procreate: StreamLine (speed-dependent pull with catch-up on lift), separate Stabilisation and Motion filtering, 250-step undo, two-finger tap undo and *two-finger hold for rapid undo*, size/opacity side sliders, pressure curve edited per device. Krita: several smoothing modes (basic, weighted, stabiliser with delay distance, pixel-based). Clip Studio: stabilisation plus "post-correction" and speed-based smoothing; draws a sample stroke to *adjust pressure from your own strokes*. Infinite Painter: predictive stroke drawing and pressure calibration by drawing. The common thread: smoothing is time/speed-based, not per-event, and pressure is tuned from real strokes.

**Measured** (1280×800 @ DPR 2, 2560×1600 canvas, 3 layers, 240 Hz pen delivered as rAF-aligned pointermoves carrying 4 coalesced samples; SwiftShader CPU raster, so absolute numbers are ~50–100× a tablet GPU — compare relative costs. `node test/perf.cjs <brush>`):
| | before | after |
|---|---|---|
| input handler per frame (Studio Ink, 80 dabs) | 1.5 ms | 0.4 ms |
| render per frame | 48 ms | 47 ms (4.1 Mpx full-screen present dominates; composite only 0.07 Mpx/frame) |
| stroke end (warm, 2050×1020 doc-px bbox) | 99 ms, incl. two blocking `readPixels` of 8 MB | 54 ms, zero readbacks |
| first stroke of a session | +100–350 ms shader JIT | pre-warmed at document creation |
| 14-stroke smoke test | 6.6 s | 1.9 s |
On a real GPU the old stroke end stalled the pipeline twice per stroke (sync readback); the new one is three scissored GPU passes.

**Rough edges found → fixed**
- Stroke end read the whole bbox back to the CPU twice (before + after) and baked the *full canvas* → GPU stash of only the bbox (blit), scissored bake, swap-semantics undo (one buffer per step serves undo and redo, half the memory). Stashes beyond a 160 MB GPU budget migrate to CPU memory by async PBO + fence readback in idle frames, never stalling. Clear/Fill/Merge undo uses the same stash.
- Smoothing was a per-event exponential, so lag and strength changed with the device's sample rate and cut corners at speed (0.7 smoothing, 60 Hz, fast: 5.3 px RMS deviation, 48 px lag) → time-based adaptive filter (heavy when slow, light when fast; speed measured in *screen* px so it feels the same at any zoom) plus quadratic mid-point curve interpolation between samples (no polygonal corners at 60 Hz). Same case now 2.0 px deviation, 26 px lag; slow-stroke jitter down 25–45 %. Remaining lag at low smoothing is mostly the half-sample of curve interpolation (≈3 px at 240 Hz).
- Pressure was a single gamma slider → Bézier curve editor with draggable handles, Soft/Linear/Firm presets, live pen dot, and **draw-to-calibrate**: scribble in a pad, Gesso fits the curve to the quantiles of your own pressure (light hand: 0.25 → 0.47) and shows the histogram behind the curve.
- Tapers were fixed doc px → scale with brush size relative to its preset.
- Pen eraser end / eraser button (buttons bit 32) now erases without changing tool.
- Two-finger hold = rapid undo (accelerating), so deep undo no longer means dozens of taps. Undo reach 120 → 250 steps.
- Mipmaps were regenerated on every present when zoomed out, even pan-only frames → only when the composite changed.
- Touch targets: small icon buttons 36 → 44 px, chips 44 px min, rail sliders 40×180.
- Brush settings wrote localStorage on every slider move → debounced.
- "Oil Bristle" tip had a bald band (random hair placement) → stratified hairs.
- In-app label "StreamLine" (another app's feature name) → "Smoothing".

**Deferred:** tiled canvases; predicted events (getPredictedEvents) for a provisional stroke tip; per-pen curves; caching below/above-layer composites during a stroke (not needed: composite is 0.07 Mpx/frame).

## M2 feature notes (research bar → what Gesso does)
**Autosave + Gallery.** Procreate saves continuously and its gallery is a thumbnail grid with stacks, swipe actions and a "+" with canvas presets; Krita/Clip Studio rely on timed autosave files; Infinite Painter keeps projects with thumbnails. Browser apps have a specific risk the natives don't: storage eviction. Gesso: debounced save 1.2 s after any undoable change, on tab hide and pagehide; only layers whose pixels changed are read back (async PBO) and stored as deflated *premultiplied* RGBA, so a reload is bit-exact (verified: pixel+property signature identical after reload); asks for persistent storage and shows usage and protection status in the gallery footer; a save-state dot on the gallery button (amber = pending, red = failed). Gallery: open, new (presets), duplicate, rename, delete (in-app confirm, no browser dialogs), current artwork highlighted. Refinement after first pass: switching documents could abort the old document's in-flight save (lost last stroke) → saves are now serialised on a promise chain and switching awaits the flush; render loop guarded while boot reads storage; square thumbnails overflowed their 4:3 cell → contained.
**Native .gesso file.** Procreate's .procreate is a private zip (archive plist + compressed tiles); Krita's .kra is a zip close to OpenRaster; OpenRaster (.ora) is the open layered format GIMP, Krita and MyPaint all read. Gesso's file is a zip that *is* a valid ORA: `mimetype` stored first, `stack.xml` (blend modes mapped to `svg:*` ops, opacity, visibility, alpha-preserve, a Background layer when visible), `data/<uid>.png` per layer, `mergedimage.png`, `Thumbnails/thumbnail.png`, plus `manifest.json` carrying what ORA can't (clipping masks, all 18 blends, background colour, active layer). Own zip writer/reader (store + deflate-raw via Compression Streams, CRC-checked on read, damaged files rejected with a clear message) and own PNG encoder (straight alpha, per-row adaptive Sub/Up/Paeth filter, zlib via CompressionStream) — avoids the lossy premultiply round trip of canvas.toBlob. Verified: export → re-import is **bit-exact** (pixels and props), Python's zipfile/PIL validate every entry, and a hand-made Krita-style .ora with an offset, half-opacity multiply layer imports correctly. Refinement: the first cut dropped the background colour for other apps → solid Background layer added to stack.xml only.
**Shape snapping (hold to snap).** Procreate's version: hold at the end of a stroke → line/arc/ellipse/polyline/quad; keep holding and a finger gives a perfect circle/square or 15° steps; an "Edit shape" banner exposes nodes. Infinite Painter and Clip Studio rely on separate ruler/figure tools instead. Gesso: recognition with tolerances in *screen* px (same feel at any zoom) for line, arc (circumcircle fit, rejected if the stroke has real corners), polyline (every vertex must be a real corner — wavy curves stay freehand), ellipse/circle (moment fit + extent refinement), rectangle/square (oriented best fit, axis-snapped within 3°), triangle/polygon. While still holding, the pen rubber-bands the shape (line end follows, ellipses/polygons scale about their centre); a finger touch makes it perfect; after lifting, handles on an overlay (rectangle corners keep a true rectangle, line ends snap to 15° within 2°), a banner offers Done or **Freehand** (return to the hand-drawn stroke), a new stroke or any tool/menu action commits, undo while editing removes the shape; one undo step total. Same brush, closed shapes untapered with a seamless join. Measured: 160/160 correct on noisy synthetic strokes (8 kinds × 20) at normal and 2.3× wobble, 150/160 at 3.6×; 40/40 scribbles and wavy curves stay freehand. Refinements after the first pass: the rubber-band scaled from (0,0) (clone lost the snap point) → fixed; a wavy stroke snapped to a polyline → corner + straightness requirement; added Settings toggle and hold time (250–1200 ms).
**Symmetry.** Procreate: Drawing Guide → Symmetry with Vertical, Horizontal, Quadrant, Radial (fixed 8 segments), a rotational toggle, per-layer Drawing Assist, draggable centre. Krita's Multibrush offers N axes and mirror; Infinite Painter adds kaleidoscope and tiling. Gesso: Vertical, Horizontal, Quadrant and Radial with **any N from 2 to 32**, with Mirror on (kaleidoscope, dihedral group) or off (pure rotation); guide centre and rotation knob are draggable with pen or finger while the bar is open (15° detents); Assisted drawing and Show guide toggles; saved with the artwork (autosave + .gesso manifest). Replication happens at the dab level, so jitter, tapers and snapped shapes mirror exactly, and each stroke stays one undo step. Verified by pixel checks in every mode (original vs mirrored alpha equal, nothing where there should be nothing), radial 6 at all six positions, guide drag, assist off, snapped line mirrored, guide restored after reload. Not applied to Smudge (its paint pickup is order-dependent; mirrored copies would smear into each other). Refinements: a finger drag on a guide handle was swallowed by the touch-gesture path → touch moves now follow the pointer that owns the drag; the bar wrapped to three rows → two.
**Image import + transform.** Procreate: Insert a photo opens the Transform tool (Freeform / Uniform / Distort / Warp, snapping, flip, rotate 45°, fit, interpolation choice); Krita adds perspective/warp/cage; most mobile apps alias badly when a big photo is shrunk a lot. Gesso: the photo goes onto a new layer inside a transform box — drag inside to move (magnetic to canvas centre and edges, guide lines shown), corners scale uniformly (projection on the diagonal, magnetic 100 %) or freely, edge handles stretch one axis in Free mode, a knob rotates (15° detents within 2.5°), two fingers move + pinch + twist together, Flip ↔/↕, Rotate 90°, Fit, Reset, Smooth/Sharp, Cancel/Done, Enter/Esc, paste from clipboard. Rendering: premultiplied mipmapped source, trilinear when shrinking, Catmull-Rom bicubic (clamped, ringing-free) when enlarging, and edges faded by their distance in destination pixels so rotated edges are anti-aliased. One undo step ("Insert image"); cancel leaves nothing. Images larger than the GPU limit are downscaled on decode. Measured: a 1000 px 2-px checkerboard shrunk to 10 % and rotated is flat grey (mean 128, σ 0.0 — no moiré); scale/rotate/free-stretch/pinch geometry checked numerically (opposite corner and edge stay fixed, pinch keeps the centre under the fingers: ratio 1.500, 20.0°). Refinement: added magnetic 100 % and a live "scale · angle" readout.

## R2-lite — M2 part A review (2026-10-12)
Every feature exercised with synthetic pen/touch input and screenshots (`test/all.sh` runs them all; all exit 0 with no console errors): `run` (brushes, gestures, layers), `r1`, `m2` (autosave + gallery), `gessofile`, `quickshape` + `quickshape-unit`, `symmetry`, `transform`, `bigdoc`.
- **Autosave survives reload**: same artwork reopens, layer pixels and properties bit-identical (2048² two-layer doc, and a 3840×2160 five-layer doc). Symmetry guide restored too.
- **Big canvas (3840×2160, 5 layers), first measurement** → main-thread long tasks of 1.9 s (single-layer save) and 2.7 s (export) under SwiftShader. Causes: the save thumbnail re-composited the whole canvas and read it back synchronously; PNG un-premultiply/encode ran on the main thread; export did a blocking full readback. **Fixes**: thumbnails reuse the live composite (only dirty regions recomposited) with an async readback; PNG encoding moved to a Web Worker (`worker.js`, main-thread fallback); export/merged image use async readbacks; all readbacks are issued up front in GL order. **After**: single-layer save 3.9 s → 0.38 s with longest task 1.9 s → 0.11 s; `.gesso` export 9.8 s → 4.6 s with longest task 2.7 s → 0.09 s; PNG export uses the same worker path. The first save of five fresh full layers still shows one ~2.7 s task under SwiftShader (buffer copies wait on CPU rasterisation there; on a GPU these are memcpy-sized).
- Reopening the 3840×2160×5 doc from IndexedDB: 3.5 s under SwiftShader.
- Known gaps: autosave stores whole layers (tiles would make the first save of a huge doc cheaper); smudge ignores symmetry by design.

## M2 part B — Selection + transform (2026-10-12)
**Bar.** Procreate: Automatic (tap, slide to set threshold), Freehand (drag + tap polygon, tap the start node to close), Rectangle, Ellipse; Add/Subtract; Invert, Copy & Paste, Feather, Colour Fill, Clear; painting confined to the selection; the Transform tool moves the selected pixels. Krita adds grow/shrink and colour-range select. Gesso:
- Selection is a GPU mask (soft, 0..1). Painting, erasing and smudging multiply their coverage by it in the live composite *and* in the bake, so what you see while drawing is exactly what lands. Outside is shown with faint moving stripes; the 50 % contour gets marching ants drawn in the screen shader (works for any shape, including wand results, at any zoom).
- Tools: Rectangle, Ellipse, Freehand (drag adds a path, taps add straight edges, closing near the start commits), Automatic (scanline flood fill with an anti-aliased soft band; slide sideways after tapping to change the threshold live; samples the layer or all layers). New / Add / Subtract.
- Ops: Invert, Feather (separable Gaussian on the GPU), Copy & paste to a new layer, Fill (honours alpha lock), Clear, Transform, Deselect. All undoable (mask stashes migrate to CPU like pixel undo).
- Transform (toolbar ✥ or from the selection bar): lifts the selected pixels (or the whole layer) — cropped to their real bounds — into the same transform box as image import; the rest of the layer stays underneath; on Done the selection mask moves with the pixels; content + mask are **one** undo step (new history grouping). Cancel restores the layer exactly.
- Fingers keep navigating the canvas once a stylus is known (select with the pen); with no stylus, one finger selects.
Verified by pixel checks: rect/ellipse add, subtract hole, freehand loop + tap polygon, masked brush (inside 217, outside 0), fill/invert, feather profile 255 → 133 → 43 across the edge, copy to layer, wand inside/outside, selection transform moves pixels and mask by 200 px in one step and undo restores both, whole-layer transform crops to content (140×40 source). Refinements: a closed freehand loop was treated as a tap (displacement instead of path travel) and the close check read the first vertex before the drag was added → both fixed; recursive commit between transform-finish and re-entering the select tool → guarded, history grouping added; chip labels no longer wrap.
**Deferred:** distort/perspective and warp transform modes, grow/shrink selection, saving selections.

## M2 part C — Time-lapse, Distort/Warp, Refine edge (2026-10-12)
**Time-lapse. Bar.** Procreate records every step at 1080p ("Good" quality by default; 2K/4K and Lossless/HEVC-with-alpha optional per canvas), replays in-app at 30 fps with drag-to-scrub, and exports *Full length* or *30 seconds*; its 30 s cut "preserves the most important frames, more of them early on when the artwork changes rapidly". Recording can be paused or purged. Krita has a separate Recorder docker (snapshots at an interval, then FFmpeg); Clip Studio records a timelapse per canvas with an export length choice; Infinite Painter and Rebelle export process videos too. Browser constraint: no FFmpeg, so encoding must be WebCodecs (or MediaRecorder in real time).
**Gesso.** One frame per *committed step* (stroke, fill, transform, undo/redo…), read back the instant it is committed: the composite is box-filtered on the GPU to ≤1920×1080 (four bilinear taps = exact box at ½ scale; mips below that), flattened onto the background colour, read through an async PBO (never stalls), and fed to a WebCodecs encoder chosen at runtime — H.264 (hardware on Android) → VP9 → VP8, realtime mode for low CPU/battery, keyframe every 90 frames. Chunks are batched into IndexedDB packs (24 frames or 2.5 s), flushed on tab hide, copied by Duplicate and removed by Delete. Each session is a new keyframe-started *segment*, so reloads continue the same recording. Without WebCodecs, frames are stored as ≤960 px WebP and exported via MediaRecorder.
- Own **MP4 muxer** (moov-first "fast start", avc1+avcC or vp09+vpcC, stts run-lengths, stss) and **WebM muxer** (EBML, keyframe clusters, cues, last frame as a BlockGroup with explicit duration). Per-sample durations mean the 2 s end hold costs one sample, not 60 duplicated frames.
- **Full-length export is a pure remux** of the recorded bitstream when the container fits (3–8 ms for 32 steps): no decode, no re-encode, no quality loss. Otherwise (30 s cut, segments with differing configs, or MP4 wanted as H.264 from a VP9 recording) it **transcodes** with back-pressured decode→encode.
- **Short version (beats a fixed "more frames early" rule):** each step's share of the ~28 s budget follows the area it changed (from the history entry's pixel footprint) plus a uniform share so detail passes still show; shares are capped at one frame each and the excess water-filled onto the rest, then frames are sampled along the cumulative share. 3000 steps with 300 big blocking-in strokes then 2700 tiny details → 840 frames, **all 300 blocking-in steps kept**, exactly 30.0 s; 1200 uniform steps → 839 frames, 29.97 s.
- **Replay screen:** loops at 30 fps with a 2 s hold on the finished piece, slider + drag-across-picture scrubbing (keyframe-aware seeker that continues sequentially when it can), MP4/WebM choice remembered, buttons show the real lengths ("Full length · 0:03", "Short · 0:30"), Recording on/off, Delete recording.
**Measured** (SwiftShader, so GPU work shows up as CPU): 26/26 steps captured when strokes come every 140 ms (first cut coalesced captures and lost 12 of 26 → readback now issued synchronously at commit, queue pipelined); ~5.5 KB per step at 1600×1000 VP9; replay frame at index 10 decoded and drawn; exports validated by ffprobe: full WebM/MP4 = 32 frames, 3.07 s (30 fps + 2 s hold), transcoded = identical frame counts; 901-step history → 30 s version with 839 frames, 29.97 s, 634 ms to transcode at 480×320. Reload continues into segment 2.
**Refinements:** coalescing lost steps → synchronous readback + queue (merges only if the encoder falls >6 frames behind); 4×4-tap downscale per step made the big-doc save stall 9.2 s under SwiftShader → 2×2 bilinear taps at ≥½ scale (5.4 s; 3.0 s with recording off — the rest is SwiftShader rasterising the readback copies, memcpy-sized on a GPU); a delete could race the recorder's last pack → recorder drained before the delete; duplicate flushes first.
**Not done:** time-lapse inside .gesso files; 4K/lossless recording options; HEVC alpha.

**Distort / Warp. Bar.** Procreate's Transform has Freeform, Uniform, Distort (drag corners/edges independently) and Warp (a mesh you can drag anywhere, with an Advanced Mesh for more nodes); Krita has Perspective, Warp, Cage and Liquify; Clip Studio has Free Transform/Distort/Mesh Transform. Common weak spots: perspective rendered as two affine triangles (visible kink along the diagonal) and folds when a corner is dragged past another.
**Gesso.** Mode chips Uniform / Free / Distort / Warp in the transform bar, for imported photos, whole layers and selections (the mask follows the same geometry on commit; still one undo step).
- *Distort* is a true projective map (homography of the unit square), rendered on a 32×32 GPU mesh so it is perspective-correct (the image centre lands exactly on the diagonals' intersection: error 0.0000 px). Corners move alone, edge handles move both ends, inside moves all, two fingers pinch/twist all corners. A drag that would make the quad concave or folded is refused (it stops at the last valid shape).
- *Warp* is a bicubic Bézier patch (4×4 control points, net drawn dashed, curves drawn at thirds). Switching to Warp is exact (max deviation 4e-13 px). Corner nodes carry their tangent handles. **Drag anywhere on the picture**: the least-change update of the 12 non-corner control points that moves the surface point under the pen *exactly* with it (follow error 0.00 px, corners move 0.0000 px) — the picture behaves like a sheet pushed inside its frame.
- Both render through the same edge-anti-aliased sampler as the affine path (domain grown 1.5 dest px past the edge and faded by distance in destination pixels; trilinear when any part shrinks, bicubic when all of it enlarges). An identity warp reproduces the image exactly (pixel colours and a hard 1 px edge: 255 inside, 0 outside).
- Switching back to Uniform/Free fits the closest box through the current corners.
**Refinement:** programmatic mode switches left the bar showing the old mode → bar re-rendered in setMode; free-warp first moved the corners slightly (they have a small Bernstein weight) → corners pinned.

**Refine edge (grow/shrink + feather). Bar.** Procreate's selection Feather is a slider; grow/shrink is not in Procreate's selection tools (Krita: Select → Grow/Shrink/Border/Smooth by a typed amount, applied blind; Photoshop: Modify dialogs or Select and Mask with live preview). **Gesso:** "Refine edge" in the selection bar opens two live sliders — Shrink/Grow (±5 % of the canvas, up to 400 px) and Feather — with the result shown as marching ants while dragging, Apply = one undo step, Cancel/undo restores. Distances come from a **jump-flooding** pass on the GPU (exact Euclidean nearest seed in log₂(size)+1 passes, coordinates packed in RGBA8 so it needs no float textures), built lazily (inside field on first grow, outside field on first shrink), so every slider move is a single cheap pass plus the blur. Grown rectangles get properly rounded corners (pixel 15 px diagonal-out of the corner: 0; 10 px: 255), soft interiors are kept (max/min with the original). Measured on 1600×1200 under SwiftShader: first grow 1.7 s (field build; tens of ms on a GPU), then ~0.07–2 s per preview under SwiftShader.

## R2 — full M2 review (2026-10-12)
Suite: `test/all.sh 1`…`4` (split so each group fits a 2-minute shell; ~4.5 min total under SwiftShader). All groups exit 0 with **no console errors or warnings**: run, r1, m2, gessofile, quickshape(+unit 160/160), symmetry, transform, selection, bigdoc, timelapse, warp.
Re-read engine, transform, selection, autosave, timelapse. Fixed:
- Compositor now draws from an explicit draw list (`drawItems()`), so a custom list (animation frames, onion skins with tints) needs no second code path; the composite shader gained a tint (rgb + amount).
- `captureScaled` (any draw list → any size, optional flatten) replaces ad-hoc readbacks for video; it no longer samples stale mip levels (min filter set explicitly every call).
- Delete-while-recording race and duplicate-without-latest-steps (see time-lapse).
- `dom.ts` holds the shared `h()`/`$` helpers (were private to main.ts).
- Feather prompt replaced by the live Refine edge panel; undo/redo while it is open cancels it first.
Still open (device-only checks, can't be done headless): pen/finger feel of the warp and distort handles on a real tablet, encoder choice on the user's tablet (expected H.264 hardware), time-lapse CPU/battery cost there.
